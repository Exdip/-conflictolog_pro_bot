# Правила разработки CKM Quiz Pro

- Среда: PHP 8.3 и WordPress. Пользовательский интерфейс — русский.
- Multi-tenant: данные разных `tenant_id` никогда не смешивать. Проверять tenant и права при чтении, назначениях, оценке и изменении состояния.
- Использовать существующее подходящее хранилище; вторую систему хранения не создавать.
- Не добавлять scenario-specific PHP вида `if ($slug === ...)`, жёсткие ID сценариев или зависимости от тестового пользователя.
- Детерминированную бизнес-логику выполнять в PHP, не передавать дополнительному LLM. Тесты вызывают production-логику, а не её копию.
- Не изменять production-сайт, не устанавливать плагин на `ckkm.ru`, не обращаться к WPVibe и не проходить реальные игры без отдельной задачи.
- Не портить исходную рабочую версию. Сохранять исходный архив и существующие пользовательские изменения; не удалять рабочую папку.
- Использовать текущее исходное дерево. Облачная задача уже изолирована; Git worktree создавать только по явному запросу пользователя.
- Каждая завершённая задача получает новую версию. Синхронно обновлять WordPress plugin header `Version` и `CKM_QUIZ_PRO_VERSION`.
- Порядок: один функциональный блок → автоматические тесты → ZIP с корнем `ckm198` → один live smoke-test отдельно.
- Перед сборкой проверять всё PHP-дерево, изменённые JS через `node --check`, новый regression suite и существующие regression-проверки.
- Если PHP CLI отсутствует, использовать существующий `php-parser` и писать именно `php-parser PASS`, а не `php -l PASS`. Проверка парсером не заменяет выполнение regression suite.
- Не утверждать, что live-проверка пройдена, если она не выполнялась. Различать статический parse, автоматические проверки с фикстурами и live smoke-test.
- При hardening сохранять порог 75 и систему из пяти критериев. Не менять корректную логику ради рефакторинга и не добавлять новый продуктовый функционал.
- В цикле «Практика → Полигон» не включать имя клиента, телефон, email, username/contact, URL и исходную переписку в игровой сценарий. Разрешены обезличенный паттерн, тип проблемы, критерий и служебная связь с source session, недоступная игроку.
