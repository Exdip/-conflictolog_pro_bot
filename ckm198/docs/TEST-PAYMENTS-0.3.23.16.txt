Тестовая оплата игр — сервер 0.1.0

УСТАНОВКА 1: centr-razvitia-uma.ru
Установить и активировать этот отдельный плагин через Плагины → Добавить.
Существующий ckm-elevenagents-home-bridge оставьте активным.
Открыть Настройки → Тестовая оплата игр.
Ввести секретный ключ ТЕСТОВОГО магазина 1441400. Он не входит в архив.
Сохранить. Скопировать показанный «Ключ связи сайтов» для ckkm.ru.
Это отдельный автоматически созданный ключ, не секрет ЮKassa.

УСТАНОВКА 2: ckkm.ru
Обновить CKM Quiz Pro архивом 0.3.23.16 с заменой.
Игровая платформа → Тестовая оплата: вставить ключ связи сайтов и включить
«Тестовую оплату и тестовый доступ». Сохранить.
Вначале тестовый режим выключен.

В тестовом магазине 1441400 указать события payment.succeeded и payment.canceled:
https://centr-razvitia-uma.ru/ckm/api/yookassa-webhook.php
Адрес остаётся прежним. Тестовый модуль обрабатывает только известные ему платежи.
Рабочие платежи 1205206 продолжают обрабатываться существующим плагином.
Его настройки, ключи, таблицы продаж и старый webhook-файл не изменяются.

ПРОВЕРКА
Открыть ckkm.ru/ckm-organizer/ под организатором.
Выбрать одну или несколько игр → Перейти к оплате.
Использовать тестовые данные из официальной документации ЮKassa:
https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing
После возврата страница запрашивает подтверждение на сервере, затем открывает кабинет.
Сумма трёх игр: 5470 ₽. Срок каждого доступа: 30 дней от подтверждения.
Обновление страницы/повтор уведомления не создаёт повторный доступ.
При отмене доступ не выдаётся. Неоплаченный формат не доступен для запуска
в тестовом режиме. Для проверки «до оплаты» нужна учётная запись без доступа.

ТЕХНИКА
REST POST /ckm-test-pay/v1/create и /status: запросы и ответы подписаны HMAC.
Цена вычисляется на сервере из каталога. Клиентские цены не используются.
Проверяются test=true, account_id=1441400, валюта, сумма, metadata и payment id.
Повтор создания использует тот же Idempotence-Key; неизвестный результат
не преобразуется в подтверждённую оплату. После 22 часов новая попытка клиента
получает новый номер заказа; старые незавершённые попытки могут ещё существовать.
Таблица сервера: wp_ckmts_orders (с действительным префиксом WordPress).
На клиенте: wp_ckmqp_test_orders и wp_ckmqp_test_access, InnoDB.
Доступ начисляется атомарно на все игры; ключ order_id+format_key защищает от дублей.
При выключении тестового режима отдельные тестовые доступы перестают учитываться.
Этот этап не обрабатывает возвраты; это тестовый контур для трёх текущих игр.
Фискальные чеки в тестовый запрос не включены: если тестовый магазин требует чек,
его настройка потребует отдельного согласования состава чека.
Серверный модуль PHP 7.4+; клиент сохраняет требования PHP 8.3+, WordPress 6.9+.
Установка, соединение сайтов и тестовый платёж на хостинге ещё не выполнялись.
